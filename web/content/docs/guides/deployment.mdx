ProxyWhirl deployments combine a Python runtime (CLI, API, or MCP), optional SQLite storage, and periodically refreshed proxy-list artifacts.

## Pre-Deploy Validation

```bash
uv run proxywhirl sources --validate --fail-on-unhealthy --timeout 5 --concurrency 5
just quality-gates
pnpm --dir web run docs:generate && pnpm --dir web run build
```

## Docker Compose (API Only)

Root [`docker-compose.yml`](https://github.com/wyattowalsh/proxywhirl/blob/main/docker-compose.yml) runs the REST API with persistent storage:

```bash
docker compose up -d
curl http://localhost:8000/api/health
```

This root stack is explicitly local-only: it publishes the API on host
`127.0.0.1`, declares the container's effective `0.0.0.0` listener through
`PROXYWHIRL_BIND_HOST`, and selects `PROXYWHIRL_ALLOW_INSECURE_BIND=1`. Before
sharing the port, remove that override and configure both
`PROXYWHIRL_REQUIRE_AUTH=true` and a non-placeholder `PROXYWHIRL_API_KEY`.

## Docker Compose (Full Stack)

[`deploy/docker-compose.yml`](https://github.com/wyattowalsh/proxywhirl/blob/main/deploy/docker-compose.yml) adds Redis, Prometheus, and Grafana while retaining SQLite as the supported persistent backend:

```bash
docker compose -f deploy/docker-compose.yml up -d
```

| Service | URL |
| ------- | --- |
| API | http://localhost:8000 |
| Prometheus | http://localhost:9091 |
| Grafana | http://localhost:3000 |

> [!WARNING]
> Grafana does **not** ship with a documented `admin/admin` default in this stack.
> `deploy/docker-compose.yml` requires `GRAFANA_ADMIN_PASSWORD` (see `GF_SECURITY_ADMIN_PASSWORD`)
> and binds Grafana to `127.0.0.1:3000`. Set a strong password in your local `.env` before `compose up`;
> never commit real credentials.

Build context resolves to the repo-root `Dockerfile` (`context: ..` from `deploy/`).

## Kubernetes

### Raw manifests

```bash
kubectl apply -f deploy/kubernetes/
kubectl get pods -n proxywhirl
kubectl logs -n proxywhirl -l app=proxywhirl
```

Before applying the raw Ingress example, replace `proxywhirl.example.com` and ensure the
`ingress-nginx` controller and cert-manager issuer named in the manifest exist. The bundled network
policy admits ingress from namespaces named `ingress-nginx`, `monitoring`, and `proxywhirl` and
permits outbound public proxy traffic while excluding private IPv4 ranges.

### Helm (recommended)

```bash
helm install proxywhirl deploy/helm/ -n proxywhirl --create-namespace
helm upgrade proxywhirl deploy/helm/ --set persistence.size=50Gi
```

Create `proxywhirl-secrets` first or set `secrets.create=true` with local, uncommitted secret values.
Customize via `deploy/helm/values.yaml` or a local values file for image tag, persistence, metrics
exposure, and secret references.

> [!WARNING]
> The supported deployment uses SQLite on a `ReadWriteOnce` volume and therefore runs exactly one
> application replica with `Recreate` rollouts. The chart rejects `replicaCount > 1`; horizontal
> scaling is not a supported deployment mode for the current storage backend.

## AWS (Terraform)

```bash
cd deploy/terraform
terraform init
terraform plan -var-file=prod.tfvars
terraform apply -var-file=prod.tfvars
terraform output ecs_service_name
```

The Terraform directory is a partial, single-task ECS scaffold; it does not create an ALB, RDS,
ElastiCache, monitoring stack, or durable shared application storage. Review the plan and supply
those platform resources before treating it as a production deployment. Configure AWS credentials
before planning or applying.

## Linux systemd

```bash
uv sync
sudo cp deploy/systemd/*.service /etc/systemd/system/
sudo useradd -r -s /bin/false proxywhirl
sudo mkdir -p /opt/proxywhirl /var/lib/proxywhirl /var/log/proxywhirl
sudo chown proxywhirl:proxywhirl /var/lib/proxywhirl /var/log/proxywhirl
sudo systemctl daemon-reload
sudo systemctl enable --now proxywhirl
```

Environment file example (`/etc/default/proxywhirl`):

```bash
PROXYWHIRL_LOG_LEVEL=INFO
PROXYWHIRL_STORAGE_PATH=/var/lib/proxywhirl/proxywhirl.db
PROXYWHIRL_BIND_HOST=0.0.0.0
PROXYWHIRL_REQUIRE_AUTH=true
PROXYWHIRL_KEY=<fernet-key>                 # credential encryption
PROXYWHIRL_CACHE_ENCRYPTION_KEY=<fernet-key>  # L2/L3 cache encryption
PROXYWHIRL_API_KEY=<key>
# Optional only for internal Prometheus scraping:
# PROXYWHIRL_PUBLIC_METRICS=true
```

Canonical encryption env names are `PROXYWHIRL_KEY` and `PROXYWHIRL_CACHE_ENCRYPTION_KEY`. `PROXYWHIRL_ENCRYPTION_KEY` is a deprecated alias accepted only when the canonical cache key is unset.

## API Service (Direct)

```bash
PROXYWHIRL_BIND_HOST=0.0.0.0 \
PROXYWHIRL_REQUIRE_AUTH=true \
PROXYWHIRL_STORAGE_PATH=/data/proxywhirl.db \
PROXYWHIRL_API_KEY=<key> \
  uv run uvicorn proxywhirl.api:app --host 0.0.0.0 --port 8000
```

Point load balancers at `/api/ready`. See [REST API Deployment](/docs/interfaces/rest-api).

## MCP Service

```bash
PROXYWHIRL_MCP_API_KEY=<key> \
PROXYWHIRL_MCP_DB=/data/proxywhirl.db \
  uv run proxywhirl-mcp --transport http
```

See [MCP Server](/docs/interfaces/mcp).

## Production Hardening (Authentication)

> [!IMPORTANT]
> Both `PROXYWHIRL_REQUIRE_AUTH` (REST API) and `PROXYWHIRL_MCP_API_KEY` (MCP server) default to
> **disabled/unset** for local-dev ergonomics. Neither flips automatically for production — you must
> opt in explicitly. The REST API refuses a declared non-loopback bind unless auth mode and a usable
> API key are configured (or the explicit local-only override is selected). An unauthenticated loopback
> API and the unauthenticated MCP mode log a `WARNING`; treat either warning as actionable outside localhost.

1. Set `PROXYWHIRL_REQUIRE_AUTH=true` and `PROXYWHIRL_API_KEY=$(openssl rand -base64 32)` for the REST
   API; set `PROXYWHIRL_MCP_API_KEY` (or `--api-key`) for the MCP server. Rotate keys on a schedule and
   store them in a secrets manager, not in compose/env files committed to git.
2. Terminate TLS in front of the API/MCP service (Nginx/Caddy/ALB) — neither service terminates TLS
   itself.
3. Restrict `PROXYWHIRL_CORS_ORIGINS` to known origins; never combine `*` with credentials (enforced at
   import time in `proxywhirl/api/core.py`, which also logs a warning if `*` is configured).
4. `/api/stats` and `/api/metrics` require the REST API key when `PROXYWHIRL_REQUIRE_AUTH=true`.
   `/api/metrics` can be exposed without a key only by explicitly setting
   `PROXYWHIRL_PUBLIC_METRICS=true`; use that only on an internal listener or behind network policy.
5. The MCP server allows unauthenticated *read* actions by default; write actions (`add`, `remove`,
   `fetch`, `validate`, `reset_cb`, `set_strategy`) are rejected without a key unless
   `PROXYWHIRL_MCP_ALLOW_UNAUTHENTICATED_WRITES` is explicitly set — keep that variable unset in
   production.
6. Monitor the "authentication DISABLED" startup warnings (API and MCP) in log aggregation/alerting so
   a misconfigured deployment is caught before it reaches production traffic.

## Backup and Controlled Rollout

```bash
./deploy/scripts/backup-restore.sh backup
./deploy/scripts/backup-restore.sh list
./deploy/scripts/backup-restore.sh restore /path/to/backup.db.gz
./deploy/scripts/health-check.sh
```

The SQLite deployment intentionally does not claim zero-downtime or blue/green multi-writer
rollouts. Back up the database, use the declared `Recreate` strategy, and validate readiness after
the replacement instance starts.

## Monitoring

```bash
curl 'http://localhost:9091/api/v1/query?query=proxywhirl_proxies_healthy'
kubectl port-forward -n proxywhirl svc/grafana 3000:3000
```

Check Grafana for error rate, latency, available proxies, and cache hit rate.
